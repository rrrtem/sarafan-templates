# Сарафан — инструкция для ИИ-агентов

Библиотека содержит HTML-карточки 1080 × 1350 px, правила бренда, шрифты, изображения, маски и примеры публикаций. Это обычная статическая папка: её можно открыть локально или разместить у любого хостинга статических файлов, в корне сайта либо в подпапке. Установка зависимостей для использования карточек не нужна.

## С чего начать

1. Прочитайте [правила дизайн-системы](design-system.md) и выберите ближайшую композицию в таблице ниже.
2. Откройте [agent-manifest.json](../agent-manifest.json), затем только нужную документацию, HTML, CSS и ресурсы. Это полный файловый каталог с контрольными суммами, а не пакет с содержимым всех файлов.
3. Найдите `<template>` по указанному селектору в исходном [index.html](../index.html). Клонируйте нужную `.ig-card` и сохраните зависимые стили, шрифты, фотографии и SVG-маски.
4. Для готовой публикации создайте отдельную папку `posts/<id>/` и добавьте запись в [new-posts-data.js](../new-posts-data.js) по [инструкции новых постов](new-posts.md).
5. Проверьте карточку в полном размере, дождитесь загрузки шрифтов и изображений и выполните визуальную проверку перед экспортом.

[llms.txt](../llms.txt) — короткая точка входа; [AGENTS.md](../AGENTS.md) — инструкции для локальной работы; [agents.html](../agents.html) — те же входы в виде статической страницы. Их наличие помогает обнаружить материалы, но не гарантирует, что любой агент автоматически прочитает эти файлы. При передаче задания укажите ссылку на `llms.txt` или этот гид явно.

В поле `styles` манифеста перечислен переносимый набор: `downloads/tokens.css`, `downloads/fonts.css`, `cards.css` и профильный CSS. В таблице выше указаны исходные CSS композиции. Все исходные страницы каталога дополнительно подключают [catalog.css](../catalog.css): он задаёт `--paper`, `--ink`, `--blue` и общий `box-sizing: border-box`, а также оформление интерфейса. При извлечении карточки эти унаследованные значения нужно сохранить явно. Подключение одних профильных CSS без переменных и reset может изменить фон, цвет и размеры.

## Токены, шрифты и пути

[downloads/tokens.json](../downloads/tokens.json) содержит значения для программной обработки, [downloads/tokens.css](../downloads/tokens.css) — переменные с префиксом `--sarafan-` и совместимые алиасы `--paper`, `--ink`, `--blue`, `--ui-accent`, а также `--card-scale: 1`. Исходник значений — [design-system-data.js](../design-system-data.js). Токены не заменяют стили композиции.

Для самостоятельной карточки с существующими классами можно подключить нужные исходные CSS и определить зависимости каталога локально. Пример для нового файла `posts/<id>/01.html`:

```html
<link rel="stylesheet" href="../../downloads/tokens.css">
<link rel="stylesheet" href="../../downloads/fonts.css">
<link rel="stylesheet" href="../../cards.css">
<link rel="stylesheet" href="../../expert.css">
<style>
  :root {
    --paper: var(--sarafan-cream);
    --ink: var(--sarafan-brown);
    --blue: var(--sarafan-blue);
  }
  *, *::before, *::after { box-sizing: border-box; }
  html, body { margin: 0; width: 1080px; height: 1350px; }
  .ig-card { --card-scale: 1; }
</style>
```

`expert.css` в этом примере нужен для карточки эксперта; для другого макета возьмите его CSS композиции из таблицы или полный список `styles` из манифеста. [downloads/fonts.css](../downloads/fonts.css) даёт отдельный набор локальных `@font-face`; исходные CSS уже содержат используемые ими объявления, поэтому для точного копирования шаблона отдельное подключение не обязательно.

Пути в HTML считаются от HTML-файла, а `url(...)` в CSS — от местоположения CSS. После копирования карточки из корневого `index.html` в `posts/<id>/01.html` замените её `src="assets/…"` на `src="../../assets/…"`. Исходные CSS оставьте на прежнем месте: тогда их пути к фотографиям, маскам и шрифтам сохранятся. Если переносите сами CSS, перенесите и зависимые файлы либо исправьте каждый относительный `url()`.

Шаблон эксперта использует отдельное семейство `Sarafan Expert Geist`, файл `assets/expert-geist-v1.6.ttf`. Сохраните закреплённую версию 1.6: замена меняет кириллицу и переносы. Шрифты и знаки не перерисовывайте. Права и лицензия на CoFo Cinema1909 проектом не установлены; наличие файла не предоставляет права использования или распространения. Сведения об остальных включённых лицензиях — в [downloads/README.md](../downloads/README.md).

## Полный каталог файлов

[agent-manifest.json](../agent-manifest.json) имеет `schemaVersion: 1` и `base: "./"`. Его файловые пути разрешаются относительно каталога манифеста. В `files` для каждого файла указаны `path`, `mediaType`, `bytes` и `sha256`; там перечислены текущие HTML, CSS, JavaScript, документация, скрипты, изображения, SVG, шрифты и экспорты. `templates` связывает композиции с `source.path`, `source.selector`, `source.cardSelector`, списком `styles` и путём `documentation`; данные публикаций и архивы вынесены отдельно. Манифест не может содержать собственную контрольную сумму, поэтому его скачивают как точку входа отдельно от `files`.

[downloads/manifest.json](../downloads/manifest.json) — другой, старый реестр готовых ассетов для интерфейса скачивания. Он содержит объёмные встроенные SVG и PNG в base64. Не загружайте его в контекст первым: для поиска файла, размера, хеша и зависимостей используйте корневой `agent-manifest.json`. При необходимости самого payload загрузки читайте старый реестр отдельно.

Архивы отмечены в отдельном списке. Старый `sarafan-templates.zip` устарел и исключён из актуального каталога. Для полной локальной копии используйте файловый манифест и скрипт скачивания; архивы дизайн-ассетов служат дополнительным комплектом.

## Скачать библиотеку с сайта

Скачайте [scripts/download-kit.py](../scripts/download-kit.py), сохраните как `download-kit.py` и запустите с Python 3. Используется только стандартная библиотека. Вместо примера укажите URL каталога библиотеки, где доступен `agent-manifest.json`:

```sh
python3 download-kit.py https://example.org/sarafan/ --dest ./sarafan-local
```

URL может вести в корень или подпапку любого хостинга статических файлов. Скрипт сохраняет файловую структуру, проверяет размер и SHA-256 каждого скачанного файла и пропускает уже совпадающие локальные файлы. Отличающиеся файлы не заменяются без явного флага `--overwrite`.

Чтобы скачать часть библиотеки, повторяйте `--include` с путями или префиксами. Зависимости автоматически не подбираются: перечислите CSS, HTML и каталоги ресурсов, необходимые выбранной композиции. Например, этот набор скачивает исходники всех шаблонов и локальные ресурсы без готовых PNG-экспортов и постов:

```sh
python3 download-kit.py https://example.org/sarafan/ --dest ./sarafan-source \
  --include index.html --include catalog.js --include catalog.css \
  --include cards.css --include expert.css --include event.css \
  --include club.css --include intro.css --include transition.css \
  --include assets/ --include docs/ --include downloads/tokens.css \
  --include downloads/tokens.json --include downloads/fonts.css
```

Для локального HTTP-просмотра полной копии:

```sh
cd sarafan-local
python3 -m http.server 8000
```

Откройте `http://localhost:8000/index.html`. Основные страницы также поддерживают открытие с диска; HTTP удобен для автоматизированного просмотра и проверок. При передаче папки сохраняйте относительные пути и локальные ресурсы.

## Новая публикация и экспорт

Для публикации используйте настоящие материалы пользователя, тексты и подтверждённые контакты. Не заполняйте раздел демонстрационными копиями ради количества. Содержимое карточки меняйте в папке новой публикации; исходный шаблон меняйте, когда это входит в задание. Запись в `new-posts-data.js` использует пути от корня библиотеки, а HTML внутри `posts/<id>/` — пути от своего каталога. Поля `edit` и `cover` для интерактивного кадрирования и недельных обложек описаны в [docs/new-posts.md](new-posts.md).

Для афиш «Гостиной» / «Сарафан Салона» цвет кодирует календарную дату: все события одного дня оформляются в одном фоне и цвете текста. Не подбирайте цвета независимо по темам событий. Храните соответствие дат и цветов в общем файле публикации, как `posts/salon-november-09-15/day-colors.json`.

Перед снимком установите размер области 1080 × 1350 px и `--card-scale: 1`. Масштаб превью `.4` и масштаб, вычисленный `catalog.js`, предназначены для интерфейса. Дождитесь шрифтов и изображений, например в браузерной автоматизации:

```js
await page.evaluate(async () => {
  await document.fonts.ready;
  await Promise.all([...document.images].map(image => image.decode()));
});
```

`document.fonts.ready` завершает ожидание загрузки; дополнительно убедитесь, что нужное семейство действительно загрузилось, а не было заменено запасным. Проверьте отсутствие переполнения, переносы, кадрирование, SVG-маски, выбранные цвета и корректный размер PNG. Длинный текст сначала сокращайте или выбирайте другой готовый формат; не уменьшайте автоматически кегль.

После изменения HTML готовые PNG в `exports/` и рядом с постом нужно пересоздать соответствующим экспортным процессом. Если изменены публичные файлы, пересоберите машинные ресурсы:

```sh
node scripts/build-agent-resources.cjs
node scripts/test-agent-resources.cjs
python3 scripts/test-download-kit.py
```

Этот сборщик и проверки не требуют внешних зависимостей. Для экспорта дизайн-ассетов действует отдельный [процесс сборки](../downloads/README.md), в котором указаны необходимые локальные инструменты.
