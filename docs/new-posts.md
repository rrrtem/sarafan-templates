# Новые посты

Раздел `new-posts.html` показывает публикации, которые агент верстает по шаблонам каталога или создаёт в рамках дизайн-системы. Слева — список постов, справа — карточки выбранного поста и описание. До первой публикации раздел пустой.

## Добавление поста агентом

1. Создать папку `posts/<id>/`, где `<id>` — уникальное короткое имя латиницей через дефис.
2. Сверстать каждую карточку отдельным HTML-файлом: `01.html`, `02.html` и так далее. Шаблоны в `index.html` служат отправной точкой; композицию можно менять по задаче. Соблюдать `docs/design-system.md`.
3. HTML-карточка должна самостоятельно отображаться в области 1080 × 1350 px, с нулевыми полями `body`, без интерфейса каталога и внешних скриптов. Если используется `.ig-card` из `cards.css`, установить `--card-scale: 1`. Ссылки на общие стили и ресурсы из `posts/<id>/` начинаются с `../../`, например `../../cards.css` и `../../assets/…`. HTML показывается в изолированном iframe без выполнения скриптов. Локальные CSS, шрифты и изображения поддерживаются.
4. Вместо HTML можно использовать готовые изображения PNG/JPG/WebP. Экспорты хранить рядом с исходниками поста.
5. Добавить запись в массив `window.SARAFAN_POSTS` файла `new-posts-data.js`. Порядок массива определяет порядок навигации; новые посты размещать в начале.
6. Проверить саму карточку в полном размере и раздел `new-posts.html#<id>` на десктопе и телефоне. Не менять исходные шаблоны при подготовке публикации.

Контакты: Instagram указывать как `@имя`, только если аккаунт подтверждён источником или пользователем. Сайт указывать как домен или URL без `@`. Не превращать домен в Instagram-ник по совпадению написания.

## Формат записи

Пример структуры, не готовая публикация:

```js
{
  id: 'post-slug',
  title: 'Название публикации',
  description: 'Описание поста или текст публикации.\n\nАбзацы сохраняются.',
  cards: [
    { type: 'html', src: 'posts/post-slug/01.html', alt: 'Обложка публикации' },
    { type: 'image', src: 'posts/post-slug/02.png', alt: 'Вторая карточка публикации' }
  ]
}
```

`id`, `title` и `cards` обязательны. У каждой карточки нужны `src` и осмысленный `alt`; `type: 'html'` включает HTML-превью, остальные значения показывают изображение. Все пути в реестре считаются от корня библиотеки. `description` — обычный текст, HTML-разметка не исполняется. При отсутствии описания блок скрывается.

## Публикации с кадрированием

Для афиши клуба `salon-november-09-15` исходные HTML экспортируются в PNG и прозрачные слои с типографикой. Карточка с `edit` отображается в canvas 1080 × 1350: фон, исходное фото под овальной маской и прозрачный слой. Это позволяет менять фото, сохраняя исходное оформление и точный PNG-экспорт при открытии библиотеки с диска.

`edit` содержит `image` (исходное фото), `overlay` (прозрачный слой), `background`, `matte`, `slot: { x, y, width, height }` и `initial: { x, y, zoom, fit }`. Позиции `x/y` — доля доступного перемещения 0…1, масштаб — 1…3, `fit` — `cover` или `contain`. В режиме `contain` изображение целиком вписывается в эллипс. Локальные media data URL регистрируются в `window.SARAFAN_CROP_MEDIA`; файл с ними должен быть подключён до `photo-crop.js`, `photo-editor.js` и `new-posts.js`.

Настройки сохраняются только в браузере, PNG скачивается с применённым кадром. Оригиналы и статические экспорты не перезаписываются. Подробности и воспроизводимая сборка: [папка публикации](../posts/salon-november-09-15/README.md).

У недельной обложки поле `cover` задаёт списки `palettes` и `layouts`, исходный выбор `initial` и отображение сочетаний `variants` в PNG. `weekly-cover.js` показывает оба переключателя, сохраняет выбор и скачивает выбранный вариант. `scripts/weekly-cover.cjs` собирает исходники по `cover.json`; экспорт вызывается из сборщика недельной публикации.

Новые посты добавляются только после создания реальных материалов. Не наполнять раздел демонстрационными публикациями или копиями шаблонов ради заполнения интерфейса.
