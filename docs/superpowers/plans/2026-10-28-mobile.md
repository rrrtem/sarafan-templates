# Mobile library adaptation

**Goal:** Make all existing template browsing, publication selection, downloads,
cover controls, cropping and design resources comfortable on a phone.

**Approach:** Keep the static HTML/CSS/JavaScript architecture and existing brand.
Use responsive controls around the original 1080 × 1350 artwork. Reuse existing
crop and cover engines and saved settings. No dependencies or deployment changes.

- [x] Reproduce mobile navigation, touch target and carousel limitations in a real browser.
- [x] Compact shared navigation; expose previous/next and return controls;
      allow opening and downloading individual cards from the overview.
- [x] Add a native publication picker; enlarge cover and crop controls;
      adapt the crop dialog to phone portrait and landscape screens.
- [x] Adapt design resource controls and check every public page at 320–768 px.
- [x] Verify touch gestures, crop save/cancel/persistence, PNG dimensions,
      filtered slides, navigation and desktop layout in Chromium.
- [x] Rebuild agent resources and run required repository checks.

Existing uncommitted content is preserved. Changes stay in the current shared
workspace so the user's ongoing publication work remains available.

## Verification

- Initial browser test reproduced undersized navigation and filter touch targets.
- `scripts/test-mobile.cjs`: passes over local HTTP; portrait 320–768 px,
  844 × 390 landscape, swipe/cancel/vertical gestures, filters, per-card actions,
  real PNG/asset downloads, scroll restoration and desktop defaults.
- `scripts/test-salon-week.cjs`: passes save/cancel/reset/Escape, drag/zoom,
  reload persistence, cover options and pixel-identical 1080 × 1350 PNG output.
- Resource integrity, static build, crop geometry, typography and all 20
  downloader tests pass.
- WebKit was attempted but its executable is not installed. Safari verification
  remains a limitation; no browser dependencies were installed.
- New previews are in `preview/mobile-*-chromium.png`.
